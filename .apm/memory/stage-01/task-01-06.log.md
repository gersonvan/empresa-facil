# Task 1.6 - Event-Sourced Backend and Sync Engine

## Summary
Bootstrapped a Node.js + Fastify backend under `server/` with PostgreSQL event-sourced schema, append-only event persistence, sync push/pull APIs, backup export, and readiness endpoints. Runtime validation was completed against a real PostgreSQL Docker container, so task status is now Success.

## Details
1. Created backend service scaffold with dedicated package and runtime entrypoints (`server/src/server.js`, `server/src/app.js`, `server/package.json`).
2. Added PostgreSQL schema migration (`server/migrations/001_init.sql`) covering append-only events, projection winner metadata, per-device sync metadata, and backup export records.
3. Implemented migration runner (`server/src/migrations.js`, `server/src/migrate.js`) and startup auto-migration behavior.
4. Implemented append-only event store (`server/src/eventStore.js`) with audit metadata fields:
   - `id`, `aggregateId`, `aggregateType`, `timestamp`, `deviceId`, `eventType`, `payload`, `reason`, `syncedAt`.
5. Implemented sync APIs:
   - `POST /api/sync/push`: batch ingest, accepted/conflicts/serverTime response.
   - `GET /api/sync/pull`: events since checkpoint (`since`, `deviceId`, `limit`).
6. Implemented deterministic conflict policy (`server/src/conflict.js`):
   - last-write-wins by timestamp,
   - tie-break by lexicographic `deviceId`,
   - final deterministic fallback by event id.
7. Implemented backup/export endpoint (`GET /api/backup/export`) and health/readiness endpoints (`/health`, `/ready`).
8. Added backend contracts (`server/src/syncContracts.js`) for progressive frontend adapter migration.
9. Added server setup/run docs and env documentation (`server/README.md`, `server/.env.example`).
10. Added backend tests for deterministic conflict resolution and migration runner behavior (`server/tests/*`).
