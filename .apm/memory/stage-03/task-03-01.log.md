# Task 3.1 - Month review, status, and approval controls

## Summary
Implemented month lifecycle controls with owner approval close, persisted state visibility, and closed-period edit protection. The review flow now supports explicit transitions with traceability and preserves evidence when a previously closed month is reopened.

## Details
1. Extended repository lifecycle behavior in `src/repository.js` with:
   - Transition constraints: `open -> in_review`, `in_review -> open`, close only through owner approval.
   - `approveAndCloseMonth` owner-only close API.
   - Closed-month write protection for create/update launch operations.
   - Traceability fields (`history`, `hasBeenClosed`, `closedAt`, `closedByRole`).
2. Added persistent month lifecycle module in `src/monthLifecycle.js` (localStorage-backed with memory fallback) to keep status visible across reloads.
3. Added TypeScript declarations in `src/monthLifecycle.d.ts` for screen-level integration.
4. Updated month-review UX in `src/screens/MonthReview.tsx` and `src/screens/MonthReview.module.css`:
   - Status-driven actions.
   - Owner approval close messaging.
   - Reopen flow preserving prior close evidence.
   - Visible audit note when month has been closed before.
5. Updated launch flow in `src/screens/Launch.tsx` and `src/screens/Launch.module.css` to block saves for closed months with clear guidance.
6. Exported lifecycle APIs from `src/index.js`.
7. Updated tests:
   - `tests/month-review-controls.test.js` for transitions, owner approval, close protection, persistence, and reopen evidence.
   - `tests/core-model.test.js` aligned to approval-based close behavior.
   - `package.json` test script includes Stage 3.1 test.
