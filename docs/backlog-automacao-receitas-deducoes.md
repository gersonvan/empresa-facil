# Backlog de Tasks - Automacao de Receitas e Deducoes

## Como ler
1. Prioridade: P0 (agora), P1 (proximo ciclo), P2 (evolucao).
2. Esforco: S (ate 1 dia), M (2 a 4 dias), L (5 dias ou mais).
3. Dependencia: task que precisa estar pronta antes.

## EPICO 1 - Fundacao de dados e governanca

### T1.1 - Estender contrato de lancamento com metadados de automacao
1. Prioridade: P0
2. Esforco: M
3. Dependencia: nenhuma
4. Entrega:
   - Campos sourceType, sourceRef, autoGenerated, confidence, suggestionReason, reviewStatus, reviewedBy, reviewedAt, linkedEntryId.
   - Migracao segura para registros existentes.
5. Pronto quando:
   - Leitura/escrita funciona sem quebrar telas atuais.
   - Testes de compatibilidade de dados antigos passam.

### T1.2 - Idempotencia por referencia externa
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T1.1
4. Entrega:
   - Regra para nao duplicar lancamento com mesmo sourceType + sourceRef.
5. Pronto quando:
   - Reprocessar o mesmo evento nao cria duplicata.

### T1.3 - Auditoria e trilha de revisao
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T1.1
4. Entrega:
   - Registro de mudancas de status suggested/approved/rejected/edited.
5. Pronto quando:
   - Cada acao possui usuario, data e motivo.

## EPICO 2 - Motor de regras deterministicas

### T2.1 - Regras de receita por origem fiscal
1. Prioridade: P0
2. Esforco: L
3. Dependencia: T1.1
4. Entrega:
   - Pipeline de entrada fiscal para criar receita automaticamente.
5. Pronto quando:
   - Casos validos geram receita correta sem ajuste manual.

### T2.2 - Regras de deducao por cancelamento e desconto incondicional
1. Prioridade: P0
2. Esforco: L
3. Dependencia: T1.1
4. Entrega:
   - Criacao automatica de deducao vinculada a receita quando houver evidencia objetiva.
5. Pronto quando:
   - Deducao entra no grupo correto e impacta base Simples conforme regra existente.

### T2.3 - Regras de conciliacao por cobranca/extrato
1. Prioridade: P1
2. Esforco: L
3. Dependencia: T2.1
4. Entrega:
   - Matching de recebimento com documento para confirmar receita.
5. Pronto quando:
   - Taxa de match automatica atinge meta definida no piloto.

## EPICO 3 - Fila de revisao operacional

### T3.1 - Tela Itens para revisao
1. Prioridade: P0
2. Esforco: L
3. Dependencia: T1.3
4. Entrega:
   - Lista com filtros por mes, tipo, confianca e status.
5. Pronto quando:
   - Usuario consegue aprovar/rejeitar item sem sair da fila.

### T3.2 - Acoes em lote
1. Prioridade: P1
2. Esforco: M
3. Dependencia: T3.1
4. Entrega:
   - Aprovar/rejeitar/recategorizar multiplos itens.
5. Pronto quando:
   - Operacao em lote mantem auditoria por item.

### T3.3 - Preview de impacto
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T3.1
4. Entrega:
   - Mostrar impacto no DRE e base Simples antes da aprovacao.
5. Pronto quando:
   - Revisao exibe deltas de receita, deducao, despesas e base.

## EPICO 4 - Assistencia por IA (com guardrails)

### T4.1 - Classificador de sugestao para casos ambiguos
1. Prioridade: P1
2. Esforco: L
3. Dependencia: T2.2, T3.1
4. Entrega:
   - Sugestao de grupo DRE e categoria com score e justificativa.
5. Pronto quando:
   - Score e motivo aparecem na fila de revisao.

### T4.2 - Limiar de autopromocao controlada
1. Prioridade: P2
2. Esforco: M
3. Dependencia: T4.1
4. Entrega:
   - Politica para pre-aprovar apenas alta confianca em mes aberto.
5. Pronto quando:
   - Itens abaixo do limiar nunca pulam revisao.

### T4.3 - Loop de melhoria supervisionada
1. Prioridade: P2
2. Esforco: M
3. Dependencia: T4.1
4. Entrega:
   - Captura decisao humana para melhorar sugestoes futuras.
5. Pronto quando:
   - Relatorio mensal mostra evolucao de precisao.

## EPICO 5 - Qualidade, seguranca e rollout

### T5.1 - Suite de testes de regressao financeira
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T2.2
4. Entrega:
   - Casos de receita, deducao, cancelamento, desconto e estorno.
5. Pronto quando:
   - Calculos permanecem deterministas para os mesmos insumos.

### T5.2 - Feature flags por modulo
1. Prioridade: P1
2. Esforco: S
3. Dependencia: T2.2
4. Entrega:
   - Ativar/desativar automacao por tipo de origem.
5. Pronto quando:
   - Possivel rollback sem migracao manual.

### T5.3 - Piloto com metas operacionais
1. Prioridade: P1
2. Esforco: M
3. Dependencia: T3.3, T5.1
4. Entrega:
   - Rodar piloto com usuarios internos e coletar KPIs.
5. Pronto quando:
   - Metas minimas de tempo de revisao e taxa de erro sao atendidas.

## Ordem recomendada de execucao (MVP)
1. T1.1 -> T1.2 -> T1.3
2. T2.1 -> T2.2
3. T3.1 -> T3.3
4. T5.1

## Marcos de entrega
1. Marco A (base pronta): Epico 1 completo.
2. Marco B (automacao util): Epico 2 completo.
3. Marco C (operacao segura): T3.1 + T3.3 + T5.1 completos.

## Riscos e mitigacao
1. Risco: classificacao indevida.
   - Mitigacao: revisao obrigatoria por padrao e explicabilidade.
2. Risco: duplicidade de eventos externos.
   - Mitigacao: idempotencia por sourceRef.
3. Risco: perda de confianca do usuario.
   - Mitigacao: preview de impacto e trilha de auditoria clara.
