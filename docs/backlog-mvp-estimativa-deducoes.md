# Backlog de Tasks - MVP Estimativa Automatica de Deducoes

## Como ler
1. Prioridade: P0 (agora), P1 (proximo ciclo), P2 (evolucao).
2. Esforco: S (ate 1 dia), M (2 a 4 dias), L (5 dias ou mais).
3. Dependencia: task que precisa estar pronta antes.

## EPICO 1 - Dados base e configuracao

### T1.1 - Perfil tributario por empresa
1. Prioridade: P0
2. Esforco: M
3. Dependencia: nenhuma
4. Entrega:
- Persistir perfil com annualRevenueForecast e reviewPolicy.
- Validar limites minimos (forecast > 0).
5. Pronto quando:
- Empresa consegue salvar e editar perfil sem quebrar fluxos atuais.

### T1.2 - Tabela de faixas de estimativa
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T1.1
4. Entrega:
- Tabela de faixas ate 1.000.000 com aliquota estimada configuravel.
- Faixas sem sobreposicao e com cobertura continua.
5. Pronto quando:
- Sistema seleciona exatamente uma faixa valida para o forecast.

### T1.3 - Metadados de estimativa no lancamento
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T1.1
4. Entrega:
- sourceType=tax_estimation, autoGenerated, reviewStatus, linkedEntryId e estimationSnapshot.
5. Pronto quando:
- Leitura de dados legados continua funcionando.

## EPICO 2 - Motor de estimativa e idempotencia

### T2.1 - Regra automatica de deducao ao salvar receita
1. Prioridade: P0
2. Esforco: L
3. Dependencia: T1.2, T1.3
4. Entrega:
- Ao salvar receita empresarial elegivel, criar deducao prevista vinculada.
- Formula: deducaoPrevista = receita * (aliquotaEstimativa/100).
5. Pronto quando:
- Receita elegivel sempre gera deducao prevista correta em mes aberto.

### T2.2 - Idempotencia por receita vinculada
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T2.1
4. Entrega:
- Chave unica por companyId + month + linkedEntryId + sourceType + formulaVersion.
5. Pronto quando:
- Reprocessar evento de receita nao gera duplicatas.

### T2.3 - Recalculo por alteracao/remocao da receita
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T2.2
4. Entrega:
- Editar receita recalcula deducao vinculada.
- Remover receita remove/inativa deducao vinculada.
5. Pronto quando:
- Vinculo origem-deducao permanece consistente apos mudancas.

## EPICO 3 - Revisao mensal e reconciliacao

### T3.1 - Painel de deducoes previstas
1. Prioridade: P1
2. Esforco: L
3. Dependencia: T2.3
4. Entrega:
- Lista por mes com filtros e status.
- Acoes: aprovar, editar, rejeitar.
5. Pronto quando:
- Usuario revisa itens sem sair do fluxo mensal.

### T3.2 - Reconciliacao previsto vs real
1. Prioridade: P1
2. Esforco: M
3. Dependencia: T3.1
4. Entrega:
- Informar total real do mes.
- Gerar lancamento de ajuste e marcar reconciliacao.
5. Pronto quando:
- Mes fecha com diferenca zerada via ajuste.

### T3.3 - Bloqueio por mes fechado
1. Prioridade: P0
2. Esforco: S
3. Dependencia: T2.1
4. Entrega:
- Impedir geracao e alteracao automatica em mes fechado.
5. Pronto quando:
- Qualquer tentativa em mes fechado e bloqueada com mensagem clara.

## EPICO 4 - Auditoria e confiabilidade

### T4.1 - Historico de eventos de estimativa
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T2.3
4. Entrega:
- Registrar created, recalculated, adjusted, rejected, reconciled.
5. Pronto quando:
- Cada evento possui actorRole, timestamp e motivo.

### T4.2 - Versionamento da formula
1. Prioridade: P0
2. Esforco: S
3. Dependencia: T2.1
4. Entrega:
- formulaVersion no snapshot e regra de compatibilidade historica.
5. Pronto quando:
- Mudanca de regra nao altera historico antigo.

## EPICO 5 - Qualidade e rollout

### T5.1 - Suite de testes de estimativa
1. Prioridade: P0
2. Esforco: M
3. Dependencia: T2.3
4. Entrega:
- Casos: geracao, idempotencia, recalculo, bloqueio mes fechado, reconciliacao.
5. Pronto quando:
- Testes passam de forma deterministica.

### T5.2 - Flag de funcionalidade
1. Prioridade: P1
2. Esforco: S
3. Dependencia: T2.1
4. Entrega:
- Flag para ativar/desativar estimativa automatica por ambiente.
5. Pronto quando:
- Possivel rollback sem migracao manual.

## Ordem recomendada de execucao (MVP)
1. T1.1 -> T1.2 -> T1.3
2. T2.1 -> T2.2 -> T2.3
3. T3.3 -> T4.1 -> T4.2
4. T5.1
5. T3.1 -> T3.2 -> T5.2

## Marcos de entrega
1. Marco A (base): Epico 1 completo.
2. Marco B (motor): Epico 2 + T3.3 completos.
3. Marco C (controle): Epico 4 + T5.1 completos.
4. Marco D (operacao): T3.1 + T3.2 + T5.2 completos.
